# 客户端数据同步：实现与迁移状态

本实现按 [架构方案](client-data-sync.md) 的迁移顺序，先打通设置和目录域的完整链路。这里区分已实现行为与后续迁移，不能把方案中的目标视为现状。

## 已接入的读取链路

```text
Station 业务表 / 配置协调器
  → 同事务公开投影、revision 与持久水位
  → 授权后的冻结分页 / 增量
  → ClientStore 暂存页
  → 完整批次提交实体、删除记录与游标
  → 共享 Catalog / Device / Profiles / Agents
  → 桌面订阅、Android 本地读取与版本订阅
```

目录域覆盖设备公开详情、队员、Profile/Provider、会话与任务摘要、文件元数据和会话末条消息标记。文件内容不进入目录复制；凭据不进入公开投影。任务摘要不携带完整目标或结果正文，文件标题由本地任务/队员关系投影。

Android 设置页先通过独立本地通道读取，再刷新。打开的设置页用 core 返回的不透明版本检查变化，没有新版本时不重新传输完整列表。普通目录读取也复用相同投影；生命周期恢复会启动已配对设备的共享状态，暂停会停止观察任务。聊天发送没有因此获得自动重试。

Profile 和设备配置仍由现有文件持有权威。独立协调器先订阅变更，再初始化及周期校验；同步读取不触发协调。某个外部来源读取失败时保留旧值，并复制该资源的可用性与错误；不会阻塞其他 SQLite 目录数据的同步，也不把失败当成空列表。

## 协议与恢复

- 游标绑定 owner、epoch、scope；当前范围为目录与显式会话范围。UI revision 与消息顺序不充当同步游标。
- 每次导出固定同一提交视图，分页至多 512 条且受字节预算约束。客户端分页持久暂存，最后一页才发布。重复页、载荷变化、旧对象 revision、错误 owner 和页序均有校验。
- 增量使用保留最新对象版本和 tombstone 的压缩日志。维护保留边界后，旧游标返回 reset-required。冻结导出有数量和时间上限，不长期占用读事务。
- 导出和回执内部记账不广播业务失效；持久游标提示已覆盖时不继续追赶。同设备/范围的并发刷新合并，进行中的请求之后又到达的新需求仍会继续追赶。
- SQLite 单文件恢复由独立的已发水位文件检测并更换 epoch。普通重启保留 epoch。**如果恢复整个数据目录，连水位文件一起回退，恢复流程仍必须主动生成新 epoch**；本实现不声称能凭被同时回退的数据自动发现所有恢复。
- 投影 schema 升级只重建派生的 SQL 投影，并使旧导出/游标失效；业务表、身份、命令回执和文件权威不会清空。迁移只移除明确归属的投影触发器，保留同步通知等其他触发器。
- 客户端撤权增加授权代次，清理对应公开副本及下载缓存。旧连接迟到的页和回执不能越过代次检查；草稿、聊天 outbox 与未解决意图独立保留。

同步开发还须遵守 [空闲合同](sync-idle-contract.md) 和共享 [zork-sync skill](../.agents/skills/zork-sync/SKILL.md)。

## 当前已接入的命令

头像修改和任务决策使用持久命令 ID、对象基础版本、owner/epoch 绑定与回执。任务决策同时保留原来的业务 revision、任务归属、运行状态和会话串行检查。

客户端先保存意图及尝试状态，再发送；服务端将业务变化与回执放在同一事务。相同 ID、相同载荷返回原结果；不同载荷复用 ID 会被拒绝。丢失 ACK 后可查询原回执，不能自动换 ID 或重新执行。收到单对象回执可以更新该对象，但不能推进整个目录水位。不同 owner 的新意图显式校验，旧格式意图不会因此增加自动重放行为。

## 后续迁移边界

- 已验收的消息发送、LiveFeed 历史补齐和执行历史仍使用原有共享 core 路径。虽然协议和存储支持显式会话范围，本轮没有让进入会话默认复制全部历史。
- 其他配置写入尚未全部迁移为通用命令回执；Profile/config 也尚未成为 Station SQLite 内的产品权威。文件与数据库之间不能宣称原子提交。
- 历史范围覆盖、固定保留、附件配额和完整资源回收仍需随后接入；当前日志与导出保留机制不等于完整客户端空间配额。
- 存储性能、模拟器与真实用户设备是不同证据；具体结果以本次 验证记录（本地生成的验收记录） 为准。

## 回归入口

```sh
cargo test --locked -p zork-client-types -p zork-client-core -p zork-station -p zork-android
cargo build --locked -p zork -p zork-station -p zork-gh
python3 scripts/test-sync-idle.py
python3 scripts/android/test_mesh.py --serial <任务模拟器> --apk <固定主包> --test-apk <固定测试包> --output <报告目录>
cargo bench --locked -p zork-client-core --bench replica --no-run
```

性能测试先单独编译，再在没有并行构建/负载测试时运行生成的 `replica` benchmark。它测量 100000 条混合消息记录的存储、单记录增量和目录读取，不代表消息渲染或 FPS。
