# 组件交互状态规范草案

状态：已纳入 [现有设计规范](gui-approved-design.md) 的组件交互契约。按钮方向已由用户确认；其余组件按同一契约实施，进度见 [统一方案](ui-system-unification.md)。

## 目标

同类控件在不同页面有一致的反馈；保留主操作、普通操作、导航和输入的层级。
统一颜色、形状、热区、状态组合与动效，而不只是替换 hover 色值。
沿用现有暖灰、深色主按钮和柔和圆角，不引入新主题。

## 组件家族

| 家族 | 默认 | Hover | 按下／选中 |
| --- | --- | --- | --- |
| 普通操作：次按钮、图标按钮、工具栏操作 | 现有透明或浅底 | 同一中性暖灰反馈 | 按下加强背景，文字不整体变淡 |
| 可选行：导航、菜单、选择列表 | 所在容器底色 | 与普通操作同源的浅暖灰 | 选中是持久状态；hover 不覆盖选中标识 |
| 主操作：保存、发送等 | 现有深色实底 | 深色范围内的小幅变化 | 继续保留主操作层级 |
| 输入框／下拉触发器 | 现有输入底色 | 边框加强，底色保持稳定 | Focus 使用统一边框／轮廓；错误状态可同时辨认 |
| 文本操作：展开、收起、正文链接 | 文本 | 文字强调或下划线 | 不突然长出整行按钮底板 |
| 危险操作 | 既有危险语义 | 使用单独的危险状态配方 | 不因 hover 临时改变普通操作的语义 |

首轮中性 hover 以现有 `#EFEEEA` 为基准；选中保留 `#EAE7E1`；深色 hover 以现有 `#41464C` 为基准。
Pressed 等新增值放在组件状态对照中确定，不在业务页面先散落新色值。
白色内容区、暖灰侧栏、弹窗都要并排比较；若需要随底色调整，由共享主题解析，不由页面各选一种灰。

## 形状和热区

- 普通图标按钮默认沿用 32px 热区、12px 圆角。紧凑尺寸成为显式 size 变体，统一规定其热区、图标大小与圆角。
- 文字按钮保留胶囊；输入框保留现有 12px 圆角；行反馈沿用共享行组件的圆角。形状不同必须来自组件家族或尺寸。
- Hover 层继承组件轮廓，不另传一个可能与外框不同的 radius。
- 点哪里生效，反馈就覆盖哪里；文本链接可以有较大隐形热区，但不暗示整行可点。
- 仅局部按钮可点的卡片不整卡亮起。可点击整行含独立按钮时，行与按钮分工明确，按钮点击不冒泡成行操作。
- 状态切换不改变尺寸、内边距、位置或字重，不造成内容跳动。

## 状态组合

- Default、hover、pressed 是瞬时状态；selected、invalid、busy 是独立的语义状态。
- Disabled 阻断 hover、pressed 和激活；视觉变灰与事件不可触发由同一组件保障。
- Focus-visible 是键盘定位轮廓，可与 selected、hover、invalid 叠加，不能仅复用 hover 底色。
- Selected + hover 保留选中标识；pressed 结束后回到当前实际状态。
- Busy 保持控件宽度和原有语义，由组件决定是否允许再次操作。
- 鼠标进入图标、文字等子元素不应反复退出、重进 hover。状态由控件根节点持有，纯绘制层不争夺命中。
- Hover 统一使用短颜色／透明度过渡，不缩放、位移或弹跳。保留现有共享 motion 的中断能力与减少动态效果支持，静止后不继续请求帧。
- 触屏只使用 pressed／selected，不依赖 hover 才能发现关键操作。

## 组件库边界

1. `design.rs` 增加按语义命名的交互 token。`sidebar_hover` 的使用逐步迁到通用语义，避免其他页面借用侧栏名。
2. 共享状态解析负责 background、foreground、border、focus 和 motion。调用者只提供家族、尺寸和状态，不提供 hover 色值。
3. 对外提供 Button、IconButton、ActionLink、InteractiveRow／MenuItem、Field 等语义入口；保留现有组件实现作为迁移基础。
4. `shell::icon_button` 收敛为共享 IconButton 的适配器，最终移除重复绘制。页面只组合内容和业务回调。
5. `HoverFill` 作为内部绘制细节，不是页面随意传 color／radius 的通用出口。
6. 特殊控件如液态输入区允许有命名变体，但变体定义归组件库，并进入状态对照；不靠业务页面覆盖样式。

## 对照与落地顺序

第一批：共享／聊天／浏览器的普通图标按钮和安静的文字操作。先消除同类操作最明显的差异。

第二批：导航、菜单、附件行、选择列表；一起处理 selected + hover 和嵌套操作。

第三批：主按钮、输入框、禁用、忙碌和键盘焦点，收敛完整状态组合。

组件图库新增统一交互状态对照：每个家族排列 default、hover、pressed、focus-visible、disabled，以及适用的 selected + hover、invalid + focus、busy。
对照同时放在白色和暖灰容器上，复用同一套 Rust/GPUI 组件；静态状态展示之外保留真实鼠标、键盘、离开和中断操作。
检查热区、轮廓、无布局跳动、禁用行为、嵌套点击与静止后停止动画；原生与 Web 分别记录实际验证结果。

迁移后增加窄范围的规则检查：业务视图新增原始 hover 背景／圆角配方需要回到共享组件实现；品牌动画、拖拽落点等具名例外单独登记。
不一次替换所有 `hover` 调用，也不把展示内容的 group-hover、Tooltip 展开等行为机械换成按钮反馈。

第一版可交互入口：组件图库 `interaction-overview`。原生交互检查覆盖两种底色的六个操作，Web 已构建，浏览器运行时验收尚未完成。证据见 `artifacts/interaction-preview/README.md`。


## 导航 tab（2026-09-10）

- 设备、Leader、Task 和设置导航都使用 `navigation::TabGroup`。一个侧栏持有一个 group，由 `surface` 包住包含分组留白的完整侧栏，`tab` 创建控件，`column` 统一 2px 间距，`section` 统一客户端／设备设置的组标题与留白；没有单独开启滑动的选项或旧版 row 入口。
- Hover 背景在同组 tab 间连续滑动，中途改变目标接续最后绘制的位置。背景和 active 短条在整个 group 的绘制边界中移动，不按行裁剪；经过分组留白时仍完整可见，停稳后遵循目标的滚动裁剪。移入、移出、按压和减少动态效果沿用共享反馈实现。
- Active 使用左侧 2×14px 柿橙短条（`BRAND_ACCENT`，`#E9643B`），取消选中底色。切换当前页时短条独立滑动，鼠标移到其他 tab 只移动 hover；两者中途反向均接续当前位置。短条在按压背景之上绘制。
- 所有 tab 使用相同的 hover／pressed 颜色；选中不改变字号、字重或内容起点。键盘焦点继续使用独立轮廓，按下不降低文字与图标透明度。
- 保持 32px 行高、12px 圆角及内容缩进规则。原生与 Web 复用同一组件，分别记录后端验收；Android 保留 48dp 操作区，不套用桌面尺寸。

## Composer 紧凑操作（2026-09-10）

- 发送与附件操作统一使用 24px 控件、14px 图标。输入上边距 8px、输入与操作行间隔 2px、底部 6px，chrome 合计 40px；测量和液态背景使用同一组尺寸。
- 就绪的发送按钮使用 `BRAND_ACCENT` 柿橙，并复用共享 hover 动画及 `INTERACTION.accent_hover`／`accent_pressed`。空输入维持禁用灰，停止操作维持深色。
