# Rust core 与 UI 的硬边界

UI 只能承担展示、动效、输入采集和必要的瞬态交互状态。客户端所有业务逻辑、业务数据、网络请求、持久化、同步、重试和操作生命周期都必须经过 `zork-client-core`。服务端仍是其业务数据的权威；客户端 core 负责操作协调和本地投影。

## 职责与接口

| 责任                                                                   | 归属                                 |
| ---------------------------------------------------------------------- | ------------------------------------ |
| 排版、绘制、文案呈现、动效、焦点、悬停、IME、选区、滚动位置            | UI                                   |
| 将一次输入交互转换为业务意图；展示 core 的只读状态、校验错误和操作进度 | UI                                   |
| 模型/Agent 配置规则、默认值选择、权限判断、消息身份与投递状态          | Rust core                            |
| HTTP/SSE/Mesh 请求、请求参数、回执、超时、取消、退避与重连             | Rust core                            |
| 业务列表、草稿与 outbox、持久副本、去重、分页游标、冲突检测与状态发布  | Rust core                            |
| 持久化偏好、文件导入导出策略、登录流程、设备目录和客户端运行时协调     | Rust core                            |
| 系统文件选择器、剪贴板、窗口、通知呈现、浏览器引擎等系统能力           | 平台适配；经 core 定义的能力接口衔接 |

UI 可以保存未提交的输入缓冲区、字段焦点、选中的记录 ID 和派生绘制缓存。输入是否合法、操作是否允许、默认模型如何选择等由 core 返回。core 不能依赖 GPUI/Compose 类型，业务操作的正确性不能依赖某个窗口或组件仍然存在。

按钮提交 `SaveModel`、`RemoveModel`、`ConnectDevice`、`SendMessage` 等业务操作及输入值。网络方法、路径、协议字段与重试策略留在 core 内部。操作结果通过共享订阅发布；平台只应用 core 给出的快照或变化，不从 outbox 的消失推断送达，不从点击回调增删另一份业务列表。

平台能力适配不构成绕过边界的通道。系统 API 的具体调用可以由宿主实现，业务策略、授权范围与请求生命周期由 core 决定；浏览器引擎及系统对话框不能成为 UI 任意请求 Gateway 的入口。

以下做法不算完成分离：

- 将 UI 的 HTTP 调用改名为 `request` / `execute`，但仍由 UI 拼方法、路径和业务 JSON。
- 把业务代码移到 UI crate 的另一个文件，继续依赖视图字段或组件生命周期。
- 桌面与 Android 分别实现同一校验、默认值、状态归并或失败重试规则。
- 网络请求已在 core 执行，但 UI 自行合并业务数据、修复权限或补造已发送消息。

## 当前迁移状态

2026-09-11，原盘点入口已按下表接入 core。表内记录代码职责；运行时证据按文末的验证范围区分。UI 保留的是输入缓冲、选中 ID、只读呈现镜像和绘制缓存。

| 范围             | core 入口与职责                                                                                                               | 平台接入                                                                                                 |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Android 消息     | `subscriptions`、`Device`、`Conversation` 与 `Outbox` 提供消息、回执、撤回、权限及投递投影                                    | `ClientViewModel` 应用 core 快照/增量；移除根据 outbox 消失补造消息的 reducer                            |
| 模型设置         | `model_edit` 提供表单默认值、复制、校验、增删规则；`Profiles` 发布完整详情并协调提交                                          | 桌面与 JNI 使用同一模型输入契约；服务端 `update_models_checked` 在存储锁内比较预期配置，拒绝覆盖并发改动 |
| Profile 授权     | `Profiles` 管理开始、轮询、回调、超时、取消及操作代次；迟到的创建结果会撤销自身                                               | UI 展示授权状态、打开链接、采集回调；视图释放不自动取消其他订阅者的授权                                  |
| 桌面账号         | `desktop::Directory` 与 `AccountFlow` 管理 OIDC、取消、身份验证和持久化                                                       | UI 只打开 core 发布的 URL、呈现忙碌状态并提交登录/取消/退出意图                                          |
| Agent 设置       | `agent_edit` 与 `Agents::save` 提供候选模型、兼容 Profile、思考深度修复、校验与提交                                           | 桌面和 Android 不再各自修复选择或构造 Gateway 请求                                                       |
| Mesh 设置与邀请  | `MeshAdmin` 管理配置修改、成员操作、邀请与审批生命周期；手机加入由 core enrollment 管理                                       | UI 订阅配置、邀请和状态，并提交 `MeshAction`                                                             |
| 设备目录         | `desktop::Directory` 管理成员版本、节点持久化、连接绑定和状态发布                                                             | `DesktopRoot` 按 core 绑定版本复用视图；连接更换或设备移除后，旧请求不能写回目录                         |
| 节点运行时       | `desktop::node`、`desktop::transport` 管理宿主进程、配置、启动、关闭及后台接管                                                | UI 提交开关意图；系统窗口和 app 退出只提供宿主生命周期信号                                               |
| 改名、升级与诊断 | `Directory`、`SettingsAction`、`DiagnoseConnections` 管理请求与进度；升级回执匹配目标版本，重启后的未确认操作保留为待确认状态 | UI 读取结构化结果，不保留请求路径、升级确认循环或逐设备网络诊断流程                                      |
| 浏览器           | `desktop::browser`、`browser_worker`、`services` 管理授权、业务通道、服务连接和引擎进程                                       | GPUI/Android 适配窗口、画面、输入和 WebView；业务连接留在 core                                           |
| 文件、草稿与偏好 | `DraftAction`、`Device::submit_draft`、`preferences`、`locale`、`file_io` 管理编辑规则、原子提交、导入限制和持久化            | 文本编辑不覆盖同一草稿的附件；平台仅提供系统选取的路径/字节、剪贴板与保存目的地                          |
| 操作条件         | `composer` 提供发送/停止可执行状态，`subscriptions` 提供运行与取消权限                                                        | 保留桌面的中断式输入及移动端的排队输入；任务评论不会变成对 Worker 的直接停止                             |
| Android 桥接     | `Command`/`SettingsAction` 表达业务意图，core 决定本地与网络调度分类                                                          | JNI 仅转换数据和执行能力适配；网络命令在 Rust 工作线程执行，独立本地通道不等待网络锁                     |
| Web 展台         | `zork-client-core` 的 wasm 公共模块和内存适配复用 `Profiles`、`Agents` 及表单规则                                             | `zork-gui-web::api` 只提供 fixture 输入和执行器，不再跨 crate 编译 core 私有源码                         |

生产依赖已从应用 UI 移除 HTTP 客户端、数据库、Mesh、配置、OIDC 和浏览器业务实现。相应依赖位于 core；GUI 测试 fixture 可以使用 dev-dependencies。共享视觉组件仍不依赖 client core。

## 持续守护

`python3 scripts/check-client-boundary.py` 同时检查 GPUI 应用、共享组件、Android 生产代码和 Web 公共契约接入。CI 运行该扫描及 `--self-test`，覆盖依赖改名、注释/字符串伪装、测试模块遮蔽及平台 IO 通道中的业务调用。自动化截图/输入端口与 Android URI/旧偏好导入端口的 IO 例外不豁免业务路由检查。

扫描只证明可机械检查的边界；异步所有权、并发编辑、订阅归并及策略归属仍按 `zork-client-boundary` 追踪完整调用链。后续订阅性能迁移的独立进度见 `client-subscription-design.md`，不能把本次职责迁移写成所有订阅性能目标均已完成。

## 验收标准

- 桌面和 Android 的视图层不出现业务 HTTP 方法/路径/请求体、重试循环、数据库写入或自主维护的业务副本。
- 每项业务操作使用同一 core 契约，成功、失败、取消及外部更新均由订阅发布；平台映射只影响呈现。
- core 的回归覆盖撤回与回执交错、重复事件、慢订阅者、并发编辑、撤权和重连等涉及的实际行为；平台契约测试检查同一结果的映射。
- 架构检查同时覆盖共享组件与应用视图，防止新功能通过通用请求包装器绕回 UI。禁止用忽略现有违规的宽泛白名单宣称边界通过。
- 按 `zork-validation` 运行受影响检查；涉及展示或动效时再执行对应视觉、交互与性能验证。静态扫描通过不等于运行时验证通过。
