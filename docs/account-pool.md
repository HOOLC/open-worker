# 自动账号池

创建会话、创建节点 Agent 或切换模型时，可以只传 `model` 和 `thinking`。`effort` 是 `thinking` 的输入别名；响应仍使用 `thinking`。例如：

```json
{"model":"gpt-5.5","effort":"high"}
```

省略或传空 `profile_id`，以及显式传 `"auto"`，都表示自动模式；保存和返回的选择统一为 `profile_id: "auto"`。其他 Profile ID 表示固定账号，调用失败不会自动改用另一个账号。原有固定账号会话保持其选择。Station 默认模型选择也保留自动模式，不再在入口把它转换成固定账号。

桌面和 Android 的小伙伴创建、设置页面先选择模型，再选择思考深度，最后可选固定连接。模型和深度汇总各连接已启用的配置；可选连接只展示支持当前组合的账号。默认自动分配，已有固定连接和思考深度会回填。更换模型或深度导致原连接不兼容时回到自动分配；只更换连接不会清空模型和深度。

账号池是执行节点本地的 Profile 集合。多台设备各自使用本地凭据与占用状态，不传递账号凭据，不把远端设备的 Profile 混入池内。

## 分配规则

`zork-profile` 管理候选过滤、评分和调用预占，Agent 在模型调用边界申请账号：

1. 账号必须配置凭据，声明并启用请求的模型，支持指定 thinking，并具有模型上限。有图片的调用只使用支持图片输入的配置。
2. 排除账号或额度探测明确失败、任一相关额度窗口已耗尽的账号。按窗口时长识别周额度；Claude 同时检查对应模型系列的周限制，无关的 code review 等限制不影响普通调用。按量付费账号明确无余额时排除。订阅的额外 credits 为零不代表订阅额度耗尽。
3. 沿用已有订阅优先、按量付费兜底的顺序。在各计费类型内，有已知可用额度的账号先于未知额度。未知额度保留为兜底，不把旧 `unlimited` 标记当作无限余额，也不把不同单位的余额直接作大小比较。
4. 周额度得分为 `周剩余比例 / (距重置天数 / 7)`。例如 50% 一天后重置得 3.5，80% 七天后重置得 0.8。缺少重置时间按完整七天计；仅有短窗口时使用剩余比例。
5. 分数除以 `1 + 当前进行中的调用数`，同分依次比较周剩余、短窗口剩余、最近分配顺序和 Profile ID。分配与预占在同一把锁内完成；固定账号调用也计入占用。取消、失败和成功都会释放预占。
6. 后续调用优先复用上一条持久化模型结果的实际账号，前提是它仍符合条件。自动意图保存在会话选择中，实际账号保存在 `provider_context.profile_id` 中；Session SSE snapshot 的 `runtime.profile` 显示实际账号。重启后可以从历史恢复复用关系，不依赖内存分配表。新一代上下文没有旧调用记录时重新分配。

模型调用前使用所有兼容配置的保守上下文与输出预算，额度变化不会扩大预算。切换账号时，供应商连接和不匹配的加密续链不会跨账号复用；按完整可移植对话恢复调用。

## 失败与恢复

明确的鉴权拒绝或限流/额度拒绝会将账号冷却 60 秒。自动模式在本次调用尚未输出任何内容时尝试其他候选，次数以初始账号数量为限；已经输出内容时交回现有运行时错误处理，避免在同一次调用里直接重发部分结果。显式指定账号仍返回原错误，但其失败状态会影响自动池的选择。

所有候选都不可用时返回错误，不退回耗尽或冷却中的账号。之后的调用会重新检查额度缓存和冷却时间。额度使用现有后台探测结果，不在每次模型调用前请求所有供应商；过了重置时间也不凭空补满额度，等待探测确认。重新保存账号凭据会清除该账号的失败冷却。

- `cargo test --locked -p zork-agent-testkit --test account_pool --test http_api --test responses_adapter --test codex_adapter`

测试使用受控本地供应商与隔离节点，不消耗真实账号额度。
