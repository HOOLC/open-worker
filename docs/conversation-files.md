# Conversation 附件

附件的逻辑归属是 conversation，权威快照保存在 conversation 所在节点。领队聊天直接收发文件，不要求先创建任务。客户端的上传暂存和下载缓存不改变归属。

## 桌面使用

- 输入框的附件菜单选择本机普通文件，也支持拖放和粘贴剪贴板图片、文件。
- 选择时保存独立快照；文件跟随当前设备、当前会话的草稿。选择器或后台读取期间切换会话，不会把文件送到新会话。
- 附件只显示文件内容预览，在输入框右上方扇形叠放，不显示文件名、数量或大小。悬停临时展开，移开收起；点击叠放区固定展开，Escape 或点击外部收起。展开后可打开文件预览或移除草稿附件。
- 可以只发附件。点击发送后按既有 outbox 规则投递；文字与文件引用组成一条消息，目标节点拿齐文件后才接受消息并交给 Agent。
- 失败或应用重启中断后，使用消息的“重发”。文件与消息保留原 ID；重新连接不会自动重放失败请求。
- 消息中的图片按原始比例铺满圆角矩形，不显示文件名或类型；单张预览最大 300×300 px，仅宽高比超过 3:1 或低于 1:3 时居中裁切；文档使用带名称与类型的紧凑文件行，可生成缩略图时显示 72 px 预览行。点击直接打开只读预览，同一条消息内可用前后按钮或方向键切换附件。
- 大图直接显示在单层浅暖灰画布上，不再嵌套面板、显示文件信息或提供背景设置。常用操作为关闭、前后切换和缩放；另存、源码与“用于新消息”通过右键菜单访问。图片和预览操作不绘制焦点描边。SVG 保留解析结果，按查看尺寸重新栅格化。文档继续使用只读预览和更多菜单。后者引用同一份快照，保留已有草稿，不跟踪源文件后续变化。
- Esc 或点击外部关闭预览并恢复之前的焦点与消息阅读位置。图片解码失败仍可另存，文本仅显示有界开头并说明截断；缩略图在后台按可见消息加载，独立缓存，不生成待发送附件的旋转图集。
- 单文件最多 10 MiB；每条消息最多 16 个附件、总计 40 MiB。准备文件期间阻止发送，避免文字先于尚未加入草稿的文件发出。

## 领队与任务

`agent.assign` 可以传 `attachment_ids`，只允许引用调用领队 conversation 中存在的文件。目标 conversation 保存自己的副本；副本 ID 根据来源与目标确定，重试不会重复复制。

```json
{
  "worker_id": "worker-id",
  "request_id": "stable-assignment-id",
  "goal": "根据附件完善方案",
  "attachment_ids": ["file-..."]
}
```

远端任务先领取并验证输入快照，再投递 Agent mailbox。输入未到齐不会进入执行阶段。Mesh 文件读取验证配对身份、指定 executor、assignment 中的确切附件、对象来源及完整内容 hash。

`chat.post_file` 支持两种来源：

- `file_path`：当前工作区文件。
- `attachment_id`：当前 conversation 的既有附件。领队还可提供 `source_task_id`，从自己委派的任务复制一个已交付文件到领队 conversation。`agent.tasks` 返回任务的交付文件清单。

两种来源互斥。`initial_comment` 为可选说明。文件作为显式聊天消息出现，工具 invocation ID 保证同次重试幂等；它不会代替显式 final 或触发人工验收。跨节点回传先导入接收节点快照，再导入文件消息；接收后不依赖来源节点在线。复制来源保存在内部 provenance 记录中。

## 协议与存储

新增 `POST /v1/im/sessions/{session_id}/files`，请求结构：

```json
{
  "file": {
    "id": "file-<stable-id>",
    "name": "report.pdf",
    "byte_len": 12345,
    "content_root": "<full-lowercase-BLAKE3>"
  },
  "offset": 0,
  "bytes": [37, 80, 68, 70]
}
```

每块最多 24 KiB，JSON 编码后可通过既有有界 Mesh RPC。响应 `received` 表示持久保存的连续长度；重复块返回当前进度，不同内容复用 ID 或偏移被拒绝。空文件使用一块空数组。最后一块合并、验证 BLAKE3 后提交 `conversation_artifacts` 快照，并删除暂存分块。

暂存块独立存储，避免每收到一块就重写整个已接收文件。全节点最多 128 个未完成上传；超过一天的暂存在下一次上传时回收。暂存及来源记账不触发业务同步，完整文件提交才推进既有附件投影。

消息保留 `zork-files` 版本化封装，包含原文字与文件引用，不包含文件字节或客户端绝对路径。原有批注、文本附件封装可以作为内层内容。接收端在接受消息前检查每个引用是否属于该会话，并在节点受管理目录中准备 Agent 可读的文件快照。

既有 `task_artifacts` 历史与输出 API 保持兼容，其 conversation 由任务绑定的 session 决定；客户端新上传及会话间副本使用 `conversation_artifacts`。Drive 与会话文件列表继续聚合这些快照，不引入独立中心文件服务。

## 当前边界

本次接入桌面入口和共享 Rust 客户端投递；Android 尚无系统选文件入口。文件夹、超出上述限制的大文件、存储配额与缓存淘汰不在本版范围。macOS 通过 Quick Look 为文档生成缩略图；图片使用有界解码生成缩略图，按 cover 铺满纸面并居中裁切，旋转结果按文件缓存。不可预览的格式使用文件图标。图片可传输与预览；向 Agent 提供原文件路径，不自动将图片转换成模型视觉输入，也不自动解析 PDF/Office。

## 验证入口

先按本地构建规则重建相关产物，再运行进程测试：

```sh
cargo test --locked -p zork-gateway
cargo test --locked -p zork-client-core -p zork-client-types
cargo test --locked -p zork-gui --features headless-bench --test headless_conversation_files
python3 scripts/test-client-mesh.py
python3 scripts/test-conversation-files.py
python3 crates/zork-gui/tests/test_drive_artifacts.py
```

Mesh 测试使用真实传输、隔离节点和假模型，不能代替两台物理设备或真实模型视觉能力验收。

桌面附件在输入框右侧通过独立封闭孔口插入，孔口与背景共用真实几何轮廓，不使用背景色覆盖来伪造开孔。单文件直立、孔口平直；双文件对称错开且底边对齐；更多文件扇形叠放。孔宽根据实际文件占宽变化，窄孔的弧度更平。悬停时文件先浮起，再竖直平铺（最多四列）；孔口下塌为直边、圆头的圆角矩形，保留 85% 长度，收平高度不随文件数量重复压缩。插入深度使用已确认的 80 参数；展开文件的底边落在收平后的孔口处。背景在文件后方绘制，只有孔下沿的前景材料裁去文件下部，因此文件不会在输入框上边缘处被切断。

数量增加时先扩孔，再让新文件从孔中钻出，0→1 同样执行；减少时文件先缩回孔里，然后孔再收窄，最后一个移除后孔闭合。过渡期间保留离场预览，连续变更从当前显示帧直接接续 core 的最新草稿，不排队播放旧状态；静止时停止请求动画帧，减少动态效果时直接到终态。悬停/固定展开与附件数量是独立状态：删除或增加附件不强制收起，鼠标仍在区域内就保持展开，只调整文件位置；鼠标移出、Esc 或点击外部时才收回。展开后可打开文件预览或删除。删除控件以纸张右上角为中心，悬停背景为圆形，仅在指向当前文件或删除控件时显示，使用 28 px 透明点击区域及 8 px 叉号。展开为 280 ms，移出保留 120 ms 宽限后以 220 ms 收回，中途返回从当前进度反向接续。缩略图先解码并 cover 裁切，立即生成当前角度；其它角度按 0.25° 精度在后台按需生成并缓存，动画帧不解码、旋转或模糊图片。144×144 纸面按文件缓存，72×72 阴影跨文件共享，最多保留 24 份文件缓存。附件列表只由 Rust core 发布，UI 的删除、复用和发送入口不再单独回写草稿；动画消费同一订阅快照，从上一显示状态开始。

几何实现在 `zork-ui::components::attachment_fan`，原生草稿使用这份轮廓、排列与尺寸计算；消息中的已发送附件使用独立的图片缩略图和文档行；已确认的交互参考保留在 `artifacts/conversation-files/approved-design/attachment-reference.html`。

添加文件按钮直接打开系统文件选择器，不经过中间菜单。输入框外轮廓为 0.5 px，短孔描边单独使用 1 px。

附件按 core 列表的添加先后顺序显示：收拢时从左到右，展开多行时从左到右、从上到下；中心纸张的视觉尺寸不决定文件顺序。

### 统一文件预览

composer 纸面、消息缩略图和只读预览窗口复用 `views/files/content.rs` 的类型识别、文本解码和系统预览桥接。图片只在小纸面中 cover；PDF/Office 文档和文本缩略图保留整页比例。代码在预览窗口按语言高亮，Markdown 保留渲染/源码切换；SVG 的源码仍可查看。UTF-8（含 BOM）和带 BOM 的 UTF-16 LE/BE 共用 256 KiB 文本上限；空文件、编码失败、加载失败和不支持的格式分别呈现，不把二进制文件显示成原始文本。

macOS 用受限 Quick Look 子进程从附件快照生成 PDF、Office 文档和视频的首页/封面；窗口明确标注这不是完整多页浏览或媒体播放。系统不提供预览的格式、音频和压缩包仍保留文件身份与另存原文件入口。系统预览临时文件独立创建、限时清理；原始快照不修改。生成工作在后台进行，消息缓存仍有并发及数量上限，并只对已请求的行触发重测。
