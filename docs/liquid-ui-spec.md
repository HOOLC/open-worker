# 液态组件规范 · V1 提案

状态：尺寸驱动的整体液态方向已确认。本轮将「轮廓线 + 实色填充 + 液态响应」和三次 Bézier 平滑圆角整理为统一提案，并用组件样例检查覆盖范围；尚未替换生产组件。

本提案沿用 [已确认桌面设计](gui-approved-design.md) 的布局、字号、语义颜色与热区，以及 [交互状态契约](ui-interaction-states.md)。以下是视觉表面的新规则；业务行为继续遵循 [core/UI 边界](client-core-ui-boundary.md)。

## 1. 一种表面，三层职责

- **轮廓线**界定形状。普通控件使用 `#DEDFDF`，容器使用 `#EEEDEA`；默认 1 逻辑像素，填充和描边使用同一条闭合路径。
- **实色填充**表达层级和状态。保留暖白、白色、墨色、品牌橙与语义反馈色；表面不透明。主按钮依然突出，错误与禁用依然可辨。
- **液态响应**表达按压、位移、展开、收拢和内容变化。形变作用于整个表面，文字、图标保持清晰；命中区域和业务状态不随轮廓的细小波动漂移。

这套表面覆盖按钮、输入、选择器、开关、导航反馈、弹出层、卡片与对话框。正文、图标、数据图形和独立状态标记继续使用各自的绘制语义；不为文字链接增加无意义的外框。

## 2. 按实际尺寸计算

所有尺寸均为布局使用的逻辑像素。设备像素比只影响栅格化精度，不改变液态响应。

- 输入当前轮廓的宽、高、面积、周长、水平／垂直速度、宽高变化速度与稳定种子。速度来自实际呈现位置与尺寸，不以展开进度代替运动。
- 同类表面共用材料参数。特征尺度使用 `R = 2A/P`，同时保留宽高比；波数按真实宽高换算。
- 局部模态的静态响应参考 `1/k²`，恢复频率参考 `k^(3/2)`，粘性阻尼参考 `k²`。小尺度的高曲率起伏会受到更强抑制；较大表面允许更多局部流动。
- 尺寸在展开过程中连续更新。不能只给小、中、大各设一组动画，也不能仅通过 CSS/图层缩放复用同一段形变。
- 保留二维运动和惯性跟随状态。内部轮廓相对移动框架向后滞后，前缘沿运动方向轻微拉伸、横向收窄，后缘保留拖曳形变。快移比慢移更明显；急停和反向时继续计算当前状态的回稳。
- 局部模态分别接收二维相对速度在其方向上的投影。水平和垂直速度不能先相加，否则斜向运动会相互抵消；不能用同一预设波形只缩放幅度。
- 种子提供可复现的初始不对称，实际运动决定激发方向、幅度与相位变化。静止时不循环漂动。更换目标或种子时保留当前呈现状态。
- 原型中局部扰动上界为 `min(7px, 0.065R)`，整体惯性形变上界为 `min(9px, 0.1R)`，并恢复主形状的面积与质心；这是可调整的 UI 约束，不是实际流体材料参数。

该实现是受毛细波尺度关系启发的 UI 近似，仍由界面布局决定主形状。参考 [Cambridge · Surface waves](https://www.damtp.cam.ac.uk/user/tong/fluids/fluids3.pdf) 与 [Denner · Viscous capillary waves](https://arxiv.org/abs/1607.08266)。

## 3. 三次 Bézier 平滑圆角

共享 `ContinuousCorner` 路径入口。原型采用现成的 [`@msurguy/squircle-path-kit`](https://github.com/msurguy/squircle-path-kit) **1.0.0 / MIT**，直接消费其 SVG 路径；不再使用先前自拟的两段曲线公式。后续 Rust 移植应沿用上游控制点与边长预算规则。

- 默认平滑度 `0.6`，与 [Figma 的 iOS smoothing 预设](https://developers.figma.com/docs/plugins/api/properties/nodes-cornersmoothing/) 对齐；`0` 为普通圆角。
- 每个转角按「过渡三次 Bézier → 圆弧的三次 Bézier 近似 → 过渡三次 Bézier」生成。中间圆弧随平滑度变化，而非将整个转角强制压进固定的两段曲线。
- 90° 转角的边长需求为 `(1 + smoothing) × radius`。相邻圆角竞争空间时按上游算法分配预算，并收敛有效半径与平滑度；胶囊和窄控件不能强行保留放不下的平滑区。
- 填充、描边与液态主轮廓使用同一份上游路径。适配层只解析路径和采样，不重算圆角控制点；保持原有 MIT 许可声明。
- 独立圆形图形和开关滑块保持圆形，也用三次 Bézier 路径表示；头像沿用现有资源及裁切语义。
- 动态形变后的轮廓使用连续的三次 Bézier 段绘制。闭合处保持切线连续；填色、描边、裁剪和焦点轮廓共用几何来源。

运行时代码固定为 npm `1.0.0`，审阅的源码与测试固定到上游 commit `c77d38b587f8abce18cc9562b64c2f5adee6f905`。已运行库自带的 11 项 API／导出控制点对照测试；这项证据来自上游提供的 fixtures，并非本项目独立重新导出了 Figma 图形。

| 对象 | 基准尺寸与半径 |
| --- | --- |
| Composer 图标操作 | 24 × 24，14 px 图标，半径 8 |
| 紧凑／普通图标操作 | 28／32 px，半径 10／12 |
| 文字按钮 | 32 px 高，胶囊轮廓 |

## 4. 状态与动效

- 表面先声明布局边界：自由移动、固定顶边的高度展开、或固定锚点的展开。液态扰动服从这些边界。
- **高度展开**：顶边、标题区和布局宽度稳定；下边缘向下铺开，底角有可辨认的滞后与轻微向内收束，收起时连续回收。形变在固定标题区下方逐渐释放，描画范围保持在布局宽度内；不把高度增长解释为整个表面的平移，也不为恢复面积而横向鼓胀。执行历史折叠行采用此模式，保留 36 px 标题区与 12 px 圆角。
- **锚点展开**：菜单从触发器右上角向左下扩展，位置由当前宽高反推，例如 `left = anchorRight - currentWidth`。位置和大小使用同一份几何进度，原触发器的逻辑边界始终包含在展开中的逻辑边界内；收起沿同一锚点返回。
- 固定边界不参与惯性拖曳；布局型展开的面积允许随内容变化，不进行会移动锚点的全局面积／质心补偿。内容的可见区域同步跟随当前容器高度，不能提前绘制到容器外。
- 锚点约束只在固定边附近衰减，向自由区域充分释放。不能把衰减权重铺满整个表面，导致中部和自由边的液态响应也被过度压低。
- Hover 使用共享填色与描边过渡。选中、错误、忙碌和焦点是独立状态，不能被 hover 覆盖。
- 小按钮的按压仅产生轻微整体响应。小开关滑块以连贯位移为主，细碎扰动接近不可见。
- 菜单、Composer、附件展开、评论浮层和对话框的尺寸变化构成主要液态场景。
- 同组导航反馈、选项组 active 层与详情浮层复用一个表面，保留速度并连续追随新目标；不叠加多个残留表面。
- Busy 保持可预期的控件尺寸并阻断重复激活。错误保留输入，错误文本靠近对应字段；文字不随轮廓拉伸。
- 键盘焦点沿共享圆角轮廓显示。触屏保留足够热区；减少动态效果时直接应用目标形状。
- 只更新可见且变化的表面，静止后停止请求动画帧。尺寸测量、路径缓存与页面/实体生命周期一致。

| 设置 | 分段选项组 | `zork-ui/controls::choice_group` | 随客户端／后台运行的 active 表面移动 |

基础 Button、IconButton、Field、Select、InteractiveRow 的表面与状态应先统一，再组合以上组件。头像、Markdown 和代码内容保持现有表达；液态主要作用于其承载容器。

## 6. 落地与验证边界

当前交互样例用于确定视觉规范和组件覆盖，不作为原生／WASM 同源实现的验收证明。

生产落地由 `crates/zork-ui` 统一拥有平滑圆角、表面绘制与运动规则；应用只组合组件。共享 GPUI 与 WebAssembly 使用同一份 Rust 实现，业务意图、校验、持久化和操作结果继续由 `zork-client-core` 提供。

后续验证应覆盖真实尺寸、宽高比、快速反向、连续输入、种子复现、焦点／错误组合、触屏热区、减少动态效果及静止后的帧调度。原生与 Web 的实际交互、渲染耗时分别记录。

组件样例增加「运动与圆角」基准页：普通／连续圆角使用相同半径；同一面板支持拖动、慢移、快移、竖移、反向和急停。方向与速度对照共用种子及材料参数，方便区分几何基线问题和动力响应问题。
