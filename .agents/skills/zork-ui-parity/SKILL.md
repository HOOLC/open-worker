# 共享组件与设计对照

以下路径均相对仓库根目录。读取 `crates/zork-ui/README.md` 和 `crates/zork-gui-web/README.md`，修改应用视图时再读 `crates/zork-gui/README.md`。

- 视觉基础组件及资源属于 `crates/zork-ui`；应用视图由 `crates/zork-gui` 组合。共享组件不引入 Station、数据库、Mesh 或 HTTP 依赖。
- 涉及应用视图的数据、操作或平台适配时，先应用 [zork-client-boundary](../zork-client-boundary/SKILL.md)。所有业务逻辑、校验、网络与持久化经 `zork-client-core`，UI 提交业务意图；通用 HTTP 转发不算完成分离。纯视觉调整继续按本 skill 验证。
- UI 只持有 core 发布的只读投影及必要的瞬态呈现状态（焦点、悬停、动画进度及派生渲染缓存等）。按钮、拖放、粘贴等入口向 core 提交操作；通过同一订阅接收结果，不能再由各入口手工改一份 UI 业务列表。动画监听数据变化，以稳定 ID 对比前后快照并过渡；离场元素可暂留用于绘制，但不是另一份业务权威。
- 动画通常固定速度，而不是固定时长：按位移、角度或展开距离推导时长，同类运动保持一致速度；中途改变目标从当前呈现状态接续。只有明确要求固定节奏、时长或物理弹簧模型时采用对应模型，不把默认毫秒数机械用于不同距离。
- 速度曲线根据动作语义设计，不要求全部匀速或全部使用同一曲线。hover 背景是统一交互：复用 `crates/zork-ui/src/components/motion.rs` 的 `HoverFill` 和共享曲线，控件只配置颜色与形状，不能各自瞬间切换背景或硬编码另一组时长、缓动参数。移出和中途反向从当前呈现值接续。
- Web 对照编译同一份 Rust/GPUI 组件与内存适配后的应用视图，不另外用 HTML/CSS 重写控件。区分可交互 Web story 与只有原生快照的页面，不把快照当作 Web 行为验证。
- 已有设计调整从共享 tokens、组件和当前参考开始。UI 文案同时维护 GUI 两种 locale catalog，使用 `Locale::text`；用户内容和后端错误不翻译。
- 完整图库入口为 `python3 scripts/storybook/build.py`。执行前确认 `--base` 所指参考服务可用、`--output` 为任务需要的位置；不要假定脚本默认的本机服务或相邻目录在每台机器都存在。该命令会导出原生证据、捕获参考、构建 WASM 和生成图库，不负责发布。
- 只处理 Web 时读取并使用 `scripts/storybook/build_web.py`。确认目标平台支持、wasm32 target 或 rust-src、wasm-bindgen 与锁文件一致。工具链特例应局部配置，不改全局链接。当前 helper 含平台专用工具路径，其他平台先适配再运行。
- 选择 `scripts/storybook/test_package.py` 及 `uv run scripts/storybook/test_web.py` 验证；需要 fallback 验收时加 `--backend webgl`。新构建未验证时不要用 `--skip-web-build` 掩盖问题。
- 检查紧凑和宽窗口、中文字体、菜单/模态框裁剪、键盘/IME、文本选择。保留生成的截图与几何/交互报告；原生与 Web 字体栅格化差异不等同于布局回归。

交付说明共享实现改动、已验证的渲染后端与交互范围，并链接实际生成的证据。

## 正式发布与性能验收

- 个人测试设备安装遵循本地环境 skill，不自动追加以下测试；用户要求正式发布或性能验收时适用。
- 必须保证渲染和滚动性能。消息、Markdown、代码高亮、列表、文本选择、Tooltip、图片或动画的渲染改动，不能只凭编译通过、交互正确或静态截图就宣称完成；按 `../zork-validation/SKILL.md` 的渲染性能门禁验收。
- 帧内只处理可见内容。解析、语法高亮、全文拼接及不依赖布局的格式化结果应随消息内容复用；避免每帧复制整条消息、为不需要尺寸的内容做全量 shaping，或用过小的全局缓存导致往返滚动反复失效。缓存应有明确生命周期，编辑、追加、加载历史时正确失效。
- 选择高亮合并、命中检测和列表布局应避免随文本块数或样式段数平方增长；新增 Tooltip 复用共享组件，静止或滚动时不得引入持续无效刷新。
- 保留修改前后的可比较测量，覆盖长会话、不同代码块、冷首次进入及往返滚动，必要时包含选区和悬停。发现性能退化先定位并修复，不能用关闭语法高亮、文本选择等已要求的功能代替修复。
- 字体排版也属于热路径：包含大量换行的中英混排、代码、粗斜体及字号变化，检查实际注册的字体，不能只测已有 glyph/layout 缓存。共享字体实例、生成脚本和许可证；原生与 Web 不应无意使用不同字重或字体版本。

- 消息渲染的压力门禁至少覆盖 **10 万条消息**：按当前支持的内容类型混排，用户和助手角色都覆盖；文件/图片预览、活动行及待发送/发送中/失败状态按各自真实载体验证。检查开头、中段、尾部；若支持字号配置，必须确认参数实际改变渲染字号，不能只重复一种纯文本。图片等受限语法的既有回退必须明确记录。
- 消息与附件列表都必须只构建可见区域；数据增大不能让每帧工作量线性增长。统计实际消息数、可见/构建行数、解析文档数和内存，确保帧数来自真正移动的滚动。
