# 客户端状态订阅

先读[订阅设计](../../../docs/client-subscription-design.md)与[当前订阅合同](../../../docs/client-state-subscriptions.md)，并应用 [core/UI 边界](../zork-client-boundary/SKILL.md)。设计文档区分提案、迁移进度与已验证行为；以当前源码核对完成情况，不能把设计目标或历史报告当作已有能力。

目标是同一份 core 业务权威通过公共契约供各端消费，单次更新成本主要随本次变化量增长。接口命名、crate 划分、集合和通知原语可按测量与现有代码调整；保持下列语义，说明取舍并同步文档，不因本 skill 额外引入审批。

## 确定这次变化的语义

沿实际调用链检查：业务提交 → 状态与变化记录 → 订阅路由 → 平台调度 → 读取/编码 → 应用及确认 → 呈现缓存。记录本次 source、投影 key、版本作用域、所有者与数据规模，避免只优化最后一次 repaint。

- 在线状态、速率、进度等是可合并的最新状态；列表和流式正文是必须能补齐的版本化状态。可以跳过中间显示帧，不能丢失组成最终结果的数据。
- 到达动画使用累计数量及有界提示，新订阅者不回放旧动画。送达、权限、命令完成等业务事实由 core 状态机与必要的持久记录保证，不依赖 UI 消费一次回调。
- 订阅按设备、会话、记录等业务身份命名。组件名、帧时钟、焦点和滚动不进入 core。平台只机械应用快照/patch，不实现消息归并或另一套业务规则。
- 复用既有控制器和通知能力，区分网络同步提示与 UI 数据订阅；不要为每个页面新建连接、控制器或平行业务投影。新原语须有实际调用者，不能只新增一个无人接入的抽象后宣称迁移完成。
- Session 执行历史由执行节点存储；客户端按需分页读取，只在 Rust core 内存中匹配、聚合和维护查询关系，UI 消费只读结果。不为执行历史创建客户端数据库表、磁盘索引或重启恢复副本。已送达聊天消息的本地缓存另有契约；持久数据结构的版本共享不代表磁盘持久化，描述时须说清楚。
- Session 历史是 append-only，并有权威 snapshot。状态、统计和摘要从 snapshot 建立并随后续提交增量更新；聚合需求不得触发全部历史读取或客户端全量重放。只有用户明确查看具体执行记录时才获取对应历史页/详情。snapshot 缺少所需聚合字段时，应完善执行节点的快照投影或明确未知，不能隐式拉全量历史补算。
- 每次 Session SSE 连接和重连必须先返回该会话的权威 snapshot，再发送该边界之后的事件；广播落后用新 snapshot 建立基线，不扫描全部历史回放。显式历史分页只返回具体记录与分页边界，不附带 snapshot，也不为了补历史去恢复当前 runtime。

## 版本与生命周期不变条件

- 先注册订阅再读初值。首次读取明确返回快照，包括空状态。状态、revision、变化边界在同一次提交中确定；不得把不同时刻读取的状态与 patch 拼成一批。
- UI revision、对象 revision、持久副本游标彼此独立。只有同一 source 实例与投影身份下才能比较版本；重建、授权切换、窗口投影切换必须隔离旧基线。
- 增量相对于该消费者**已经应用**的版本。等待、读取、编码或投递不自动算应用成功；取消/失败保持原基线，重试从该基线补齐。原生同步应用可封装自动确认，跨线程/FFI 必须处理未应用批次。
- 每个订阅最多保留一个未应用批次。慢消费者的变化记录按条数和字节有界，超限明确 Reset 到当前订阅范围；不能只留下最后一个 producer splice，也不能默认重发全部历史。
- 增量明确 from/to 及顺序/索引含义；基线不符时拒绝应用并重新取快照。需要业务原子性的跨 source 结果由 core 聚合发布，不能交给 UI 拼接。
- 唤醒是待处理提示，不是事件计数。应用确认后重新检查版本再挂起，覆盖读取、应用及重新挂起期间的写入；等待可取消，空闲不轮询，不在持锁期间执行平台回调或重编码。
- 关闭订阅及时释放注册与任务，不等同于取消业务操作或销毁控制器。终止与最后未读状态有明确语义；FFI 使用句柄和 generation，覆盖 A→B→A 切换、关闭后的回调、撤权及在途结果。
- 相同业务输入不推进版本、不通知。由 reducer 对涉及的字段/记录判断 no-op；通用发布层不依靠整棵状态的深比较补救。

## 高频路径的要求

- 在写侧记录变化，订阅时按基线汇总；不要为每个消费者反复扫描全部历史来发现变化。不相关 topic/key 应在路由时过滤，避免全部唤醒后再丢弃。
- 大列表逐记录共享，集合更新采用有界块或持久结构，配合 ID 索引与增量统计。`Arc<Vec<Arc<T>>>` 仍复制 N 个指针，不能冒充 O(log N) 更新；前插历史也不能让 ID 索引全量重编号。
- 流式文本按块累积，只修改相关块；状态/速率变化不扫描消息正文。平台按 ID 和记录版本复用显示模型，应用一个 append 后重建完整 Kotlin List 同样属于待修复热路径。
- 合并发生在昂贵的 diff、序列化与显示模型转换之前。待处理期间只安排一次平台更新，GPUI/Compose/Web 按各自调度能力消费；core 不写死刷新率或固定毫秒数。
- GPUI 帧外订阅通知沿现有 `FrameDelivery` 投递，并核对 API 的调用阶段。`on_next_frame` 已负责唤醒帧源；不要在订阅回调里额外调用需要当前绘制视图的 `request_animation_frame`。用实际异步状态变化覆盖这一边界，静态页面截图不足以发现绘制阶段错误。
- Android 等待订阅不持有命令执行锁；编码/解码不放主线程帧回调。高频 wire 只传变化记录与必要顺序变化，大列表 Reset 使用订阅窗口/范围。
- 可合并的是通知或完整最新状态。依赖前序状态的 raw patch 不直接放进 conflated Flow/StateFlow；先顺序应用到呈现镜像，再发布可合并状态。
- 优先复用成熟原语。增加无锁结构、二进制协议或响应式依赖图要有对应测量或实际需求，不能用底层复杂度代替消除全量复制与轮询。

## 验证与持续迁移

按 [zork-validation](../zork-validation/SKILL.md)选择当前测试入口。高频实现改动先保存同条件基线，编译与性能测量分开；纯文档/skill 修改只检查结构、链接与约束的一致性，不扩展为运行全套应用测试。

- 行为检查覆盖本次涉及的首次空快照、重复输入、突发合并、慢消费者、日志超限、取消未应用批次、订阅/确认与写入交错、切换/关闭/撤权。最终呈现镜像须等于对应 core 投影，不能只断言通知次数。
- 大集合修改对比 1,000 / 10,000 / 100,000 条混合消息，覆盖单条追加、重复更新、远距离记录变化、前插历史和仅状态变化。常规小改动选择受影响场景；不要每轮机械执行全矩阵。
- 分别测提交、增量准备、编码/解码和平台应用的 p95/p99、分配与传输字节、唤醒数及保留峰值。慢消费者不阻塞快消费者，积压内存有界；无相关变化时订阅链路无持续工作。
- 存储基准、core 微基准、headless 渲染和真实设备帧率是不同证据。改到可见内容/帧调度时再按 [zork-ui-parity](../zork-ui-parity/SKILL.md)验证对应呈现；触及持久化同步或重连时应用 [zork-sync](../zork-sync/SKILL.md)。
- 随迁移更新当前订阅合同和设计稿中的实现状态，记录已接入的平台、兼容路径、实际测量与剩余工作。保留失败和未验证范围，不通过降低负载、隐藏旧路径或仅检查源码关键词宣称完成。

本 skill 守护订阅契约，不自动扩大任务为全仓业务重构、设备安装、发布或合并。后续更简单的实现只要满足同一契约并有适当证据，可以替代草图中的具体做法。
