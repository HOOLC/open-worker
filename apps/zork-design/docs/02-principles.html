设计原则

内容优先，界面保持安静

日常工作区以中性表面、细分隔和紧凑文字为主。避免用重复标题、厚重外框和大卡片稀释信息密度。插画主要用于首次使用、空状态和品牌场景。

层级清楚，点击范围一致

设备、Leader 和 Task 的层级由缩进、角色与展开关系表达。整行的 hover、选中背景保持同宽，缩进只改变内容位置。底部“添加设备”“设置”也遵守同一套导航规则。

交互不能带动排版跳动

选中与未读不改变字重、图标尺寸或行高。侧栏使用持久化像素宽度；折叠、切换、清除未读后，已有内容不应突然变宽。动效只改变视觉变换，不改变布局占位。

人物身份可辨认

已知发言者就显示其姓名与头像。Leader 与 Worker 的角色不能靠随机头像推断；头像也不承担在线、忙碌或失败的状态含义。品牌吉祥物只作为系统或缺失身份时的回退。

状态必须对应真实事实

“已接收”不等于“开始执行”，“运行结束”不等于“已验收完成”。离线不能清空已经同步的内容；没有获取到模型不能用预设目录冒充真实结果。

配置靠近所属设备

设备版本、Agent、模型连接放在设备范围内。客户端的外观和本机偏好属于客户端范围。编辑 Agent 模型不得悄悄改变身份、角色或历史任务配置。

每一步保留用户输入

草稿和评论队列按对话保存。选择文字后可逐条评论，最后通过主输入框一次发送。切换设备、离线、重连与重试不能让内容丢失或重复发送。

有明确反馈，也保留键盘路径

当前要求不使用 outline 和头像外圈。键盘焦点仍要有可见背景反馈；展开、关闭、发送和切换要有可理解的标签。仅用颜色表达状态不可取，颜色要配合图形或文字。
